# ChatGPT 반복 연구 지시문 — BUILD → RECONSTRUCT → COMPARE → REBUILD (v2)

## 최상위 목표
반복을 한 번 하고 멈추지 마십시오. 원본 거래사례가 **원문에 공개한 모든 중요 금융 사실**을 독립 지식그래프만으로 복원할 수 있을 때까지 재분석·재모델링·새 그래프 생성·재검증을 반복하십시오.

작업 순서: SOURCE → FACT_REGISTER → GRAPH_VERSION_N → SOURCE_REDACTED_GRAPH → CLEAN_CHAT_RECONSTRUCTION → SOURCE_COMPARISON → GAP_CLASSIFICATION → (FAIL: DISCARD GRAPH_VERSION_N AS CURRENT, REBUILD ENTIRE GRAPH_VERSION_N+1) → ...

**ChatGPT**가 원문 탐색·경제적 해석·거래사례 판정·지식그래프 생성·역재현·차이 분석을 담당합니다. GitHub Actions는 한 건씩 입력을 제공하고 각 반복 상태를 저장합니다. Python 금융 검색·분류·의미 검증 엔진을 추가하지 마십시오.

## 합격 기준 두 단계
1. SOURCE_FACT_COVERAGE_PASS: 사실등록부의 각 항목에 대응하는 금융 객체·속성·방향 관계가 있고, 그래프에서 원문 수치를 산술적으로 다시 얻을 수 있어야 합니다. `F01: value` 같은 출처 사실의 단순 복사나 Rule의 자유 텍스트만 읽는 것은 불합격입니다.
2. INDEPENDENT_BLIND_REPLAY_PASS: 원문을 보지 않은 **새 ChatGPT 대화**에 출처명·참고문헌·원문·정답·원문 사실등록부를 제외한 지식그래프와 온톨로지 독해규칙만 주고 독립 명세를 재작성하게 한 뒤, 비교 전용 대화가 원문과 모든 중요 사실을 대조합니다. 이 검증도 통과해야 FULL_PASS입니다.

새 대화 분리에 성공하지 못했다면 첫 단계가 통과했어도 상태를 `BLIND_PENDING`으로 유지합니다.

## 실패의 실제 원인 판정
- SOURCE_NOT_ACQUIRED: Pine 코드/원문/부록이 실제로 수집되지 않음. ChatGPT가 원문을 추가 탐색하여 확보합니다. 추측 값으로 그래프 합격 처리하지 마십시오.
- SOURCE_NOT_DISCLOSED: 원문 자체에서 예시연도·실제 거래체결·기본값을 공개하지 않았음. 해당 필드를 `NOT_DISCLOSED`로 보존하며 공개 사실 범위에서의 재현과 실제 거래 실행 재현을 구분합니다.
- EXTRACTION_MISSING: 원문에 있는데 추출하지 않음 → 원문 사실등록부와 원문 근거부터 다시 추출합니다.
- ONTOLOGY_MISSING: 표현할 노드/속성/관계가 없음 → 신규 정의의 독립 금융 의미와 예시 경로를 제안합니다.
- MODELING_WRONG: 필요한 요소가 있으나 압축·연결 방향·중간 상태·액션 순서가 틀림 → 기존 그래프에 임시 패치만 붙이지 말고 새 그래프를 전체 재생성합니다.
- RECONSTRUCTION_WRONG: 그래프는 충분하지만 별도 역재현 대화가 해석 오류 → 역재현 문맥·온톨로지 해석규칙을 수정해 새 독립 세션에서 재시험합니다.
- ORIGINAL_CONFLICT: 원문 표와 설명이 상충함 → 양쪽 버전을 출처 위치에 연결하고 임의 선택하지 않습니다.

## 매 반복마다 반드시 제출할 것
- 연구/사례 ID, 원문 URL·근거 위치, 소스 확보 상태, 온톨로지 버전
- `graph_round_N.json` — 완전히 자기완결적인 새 그래프 스냅샷
- `graph_only_input_N.json` — 근거문서/정답/기존 대화문맥을 제외한 역재현용 자료
- `reconstructed_N.json` — 그래프만으로 역재현된 거래명세와 원문 없는 상태에서 해결 불가능한 부분
- `comparison_N.json` — 원문 사실별 일치/불일치와 정확한 결손 ID, 종류, 수정 방법
- `ontology_delta_N.json` — 중복 검사를 거친 신규 노드·속성·관계 제안
- `active.json` — 지금 최신 유효 그래프 버전과 다음 동작

## 재시도와 중단 시나리오
실패라면 **완료 보고를 하지 마십시오.** 실패한 그래프의 `active` 상태를 `SUPERSEDED`로 옮기고 다음 그래프를 **처음부터 전부 재생성**하십시오. 기존 파일은 삭제하지 않고 감사·비교 이력으로 남깁니다.
GitHub Actions 실행시간 제한으로 작업이 중단되면 실행 상태를 저장한 후 다음 실행에서 다음 반복을 이어가십시오. 한 세션에서 여러 번 반복했다고 FULL_PASS로 승격하지 마십시오.
원문 확보 불가능·지원되지 않는 인증·원문 자체의 미공개를 만난다면 `SOURCE_BLOCKED`로 **미완료** 표시하고, 다음 전략을 먼저 처리하되 정기적으로 다시 확인하십시오. `SOURCE_BLOCKED`를 PASS로 계산하지 마십시오.

## 원문 재확인으로 합격 취소
소스 사실등록부가 26건이었을 때 26/26이 통과했다고 해도, 원저자 후속 글·정정·주석·댓글에서 4개가 더 발견되면 기존 합격을 **26/30 불합격으로 되돌리고** 새 전체 그래프를 생성하십시오.
처음 확보한 자료의 개수가 최종 원문 범위가 아닙니다. 원본 작성자 후속 정정과 추후 위험 설명을 검색한 뒤 source completeness를 다시 판단하십시오.
명시적 저자 정정은 원래 수치를 삭제·덮어쓰기하지 않고 `SourceCorrectionEvent → corrected metric → superseded metric` 계보로 남깁니다.
독자가 제시한 숫자는 speaker=READER 및 NOT_INDEPENDENTLY_VERIFIED로 기록하고 저자가 계산한 값처럼 제시하지 않습니다.
계약 승수×수량의 온스 수량 일치와 금액·변동성 위험 중립은 별도 `ExposureBasisComparison`으로 취급하십시오.
원문 출처 노드를 역재현 입력에서 제거하더라도 **원래 전략의 지적 출처·수식 의의 등 복원할 금융 의미**까지 소실되면 불합격입니다.
오류 비교표 자체의 이전 합격 주장이 잘못되었다면 원본 감사 파일을 보존하고 별도 corrected audit를 발행하십시오.
