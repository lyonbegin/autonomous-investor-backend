# TradingView Android 전체 모바일 웹 기능 동등성 프로젝트 — 원본 조사 단계

## 범위·현재 상태

이 브랜치는 원본 APK 전체 앱의 기능을 분석하고 모바일 웹 구현을 준비하기 위한 **독립 개발 브랜치**다. `main`, 기존 n8n 운영 관리자 UI, Railway 환경을 수정하지 않는다. 사용자의 승인 없이 시장(Markets) 8개 메뉴로 전체 앱을 축소하지 않는다.

- 분석 원본: `com.tradingview.tradingviewapp` Android 버전 `1.20.80.0.1002385`, 사용자 제공 APKM
- base.apk SHA256: `c98bbe4be3c9043ca170fd4e9d51c8446a1e5b939d84f38046dedbd1f65da038`
- 1차 기능 ID TV-001~TV-339는 그대로 유지. 358개 사용자 검수 시나리오 유지.
- 기능 원장 26영역, APK 레이아웃 XML 1111개, 전체 XML 3494개, 메뉴 XML 17개, 정적 DEX 7개.
- 2차 교차검증: 기존 원장 XML 파일 참조 불일치 0개, 브리지 정확 일치 기능 133개, 호출명 근거를 따로 써 두지 않은 기능 206개.
- 별도 검토해야 하는 원장 미연결 화면형 XML 44개 (신규 기능 44개로 계산하지 않음).
- 실제 앱 설치 및 클릭/원본 대비 화면별 픽셀 비교/로그인/실서버 데이터/모바일 웹 구현 모두 **미실시**.

## 범위 고정 정책

1. TV-001~TV-339를 삭제하거나 일괄적으로 '완료' 처리하지 않는다. Android 전용 기능은 별도의 웹/PWA 동등 구현 가능 범위 검수 후에만 판정한다.
2. 상세 화면 및 그 하위 상태까지 포함한다: 메뉴, 로딩, 에러, 비어 있음, 계정별 노출, 검색/필터, 차트, 지표, 그리기, 리플레이, 알림, 워치리스트, 아이디어, 뉴스, 경제, 브로커, 프로필, 구독, 위젯, 공유, 시스템 연계.
3. 추가 44개 화면 후보와 Compose/WebSession 화면은 실조작 검증이 끝나기 전 '범위 제외'하지 않는다.
4. 완료의 4가지 필수 증거: (a) 원본 앱 동작 확인, (b) 독립 모바일 웹 동작, (c) 실제 상태/API 및 오류 동작, (d) 화면 비교. 정적 XML 발견은 이 조건들을 대체하지 않는다.
5. 차트 자료 수집과 화면 구현을 혼동하지 않는다. 5년 1D 기간 요청, 전체 수신 봉 수와 날짜 검증을 별도 테스트한다. 분봉 5년 대량 수집이라는 불필요한 요구를 만들지 않는다.
6. 원본 XML·자바스크립트·이미지·폰트·비밀 세션을 그대로 저장소에 복제/재배포하지 않는다. 화면 기능 및 사용성을 독립 코드로 재구현한다.
7. 지금은 Cron·관리 키·기존 n8n 메뉴 병합을 임의로 만들거나 활성화하지 않는다. 마켓 메뉴 연결은 전체 앱 기능 및 사용성 검수 이후에만 진행한다.

## 근거 및 다음 작업

사용자 제공 파일의 1차 원장 `TradingView_Android_전체기능_명세.csv`, `TradingView_Android_검수시나리오.csv`와 2차 분석 패키지 `TradingView_Android_2차_분석자료_20261105.zip`을 외부 기준 문서로 사용한다. 파일을 무조건 GitHub에 원본 APK나 다운로드 데이터를 함께 커밋하지 않는다.

다음 검증은 Android 실기기/에뮬레이터를 이용한 화면·권한·지역·계정별 실행 시나리오 증거 확보다. 이 단계까지 완료되었다고 표시하지 않는다. 이후 독립 모바일 웹 작업을 진행하고, 사용자가 요청한 기능별 교차검수표를 기준으로 비교한다.
